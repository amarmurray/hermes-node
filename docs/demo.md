# Offline demonstration

This demonstration exercises the application's real task ledger, approval gate,
rate-limit handling, queue selection, and run-artifact writers. The provider is a
deterministic fake. No model, API key, network connection, subprocess, or real
repository is used.

It is an infrastructure demonstration. It does not establish model quality,
production readiness, customer adoption, or completed autonomous repository work.

## Run

From the repository root, with Python 3.10 or newer:

```bash
python3 scripts/offline_demo.py
```

No installation or `.env` file is needed. The script writes to a new temporary
directory, prints its path, and leaves its artifacts available for inspection.
To choose a location:

```bash
python3 scripts/offline_demo.py --output /tmp/my-hermes-demo
```

The chosen directory must be new or empty. The script refuses to overwrite
existing contents. It does not change the normal runtime's state directory.

## Scenario

The input contains three fictional work orders. Their summary is a fixed fixture,
not an inference from a model. The script:

1. Persists a task requiring approval and verifies it cannot run.
2. Records an explicitly simulated reviewer approval.
3. Injects a fake HTTP 429 response and records a deferred task and failed run.
4. Closes and reopens the SQLite connection to check the approval and run survive.
5. Waits for the short demo cooldown, selects the task through the real queue,
   and returns a scripted successful response.
6. Checks both run receipts and writes a machine-readable summary.

The main state sequence is `pending_approval`, `pending`,
`deferred_rate_limit`, then `done`. The normal run records also contain their
`running`, `failed`, and `done` states. Provider responses and approvals are
scripted; IDs and timestamps are generated by the application.

## What to inspect

Paths below are relative to the output directory printed by the script.

| Artifact | What it shows |
|---|---|
| `demo-summary.json` | Execution mode, state transitions, approvals, events, receipt paths, and explicit zero live-model/repository-task counts |
| `state/hermes-node.db` | Real SQLite tasks, runs, approvals, events, summaries, and cooldown state |
| `state/workspaces/<task_id>/input.md` | Synthetic task input and mock-execution metadata |
| `state/workspaces/<task_id>/runs/<run_id>/receipt.json` | Failed and successful attempt records, labeled `provider: offline-demo` |
| `stdout.txt` and `stderr.txt` beside each receipt | The scripted response or simulated rate-limit error |
| `logs/hermes-node.jsonl` | Structured wrapper lifecycle events |

The `executor: hermes_chat` field identifies the route through the application.
It does **not** mean Hermes ran: the command runner is replaced with
`ScriptedProvider`, and the recorded command is never executed. The provider's
`duration_ms: 0` is a fixture value, not a performance measurement.

## Isolation and limits

Settings are constructed directly for an empty output directory; the demo does
not load `.env`, inspect provider authentication, or discover installed Codex
executors. A non-executable placeholder takes the place of the Hermes binary.
The provider boundary is replaced using the wrapper's existing injected-runner
interface. Normal runtime code is unchanged.

The demo uses a roughly one-second retry delay so it finishes quickly. Normal
backoff defaults remain a 30-second base and 15-minute cap. The demo verifies
one deferred retry, not long-running durability or all recovery conditions.

Approval is granted by a scripted `demo-reviewer (simulated)` actor. This shows
recording and enforcement at the execution boundary; it does not test a real
human interaction, Telegram delivery, or the security of a deployed service.

## Verification

```bash
python3 -m unittest discover -s tests -p 'test_offline_demo.py' -v
```

The focused test checks persisted transitions and receipts while making external
process creation, socket connections, settings loading, and Codex auth probes
fail if attempted. It also checks that an occupied output directory is preserved.
